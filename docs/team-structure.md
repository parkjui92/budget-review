# 팀 구조 — 뜯어보기 안내

이 플러그인은 파일 몇 개로 된 **에이전트 팀**이다. 팀원 하나가 파일 하나(`agents/`), 업무 규칙 하나가 폴더 하나(`skills/`)다.
아래 순서로 열어 보면 15분 안에 팀이 어떻게 움직이는지 보인다.

## 1. 한 장 그림

```
 사용자 요청 ─▶ [팀장] 00_요청.md (글자 그대로 기록)
                  │
                  ▼
   검토설계자 ──▶ 01_검토설계.md   사업 개요 · 재원 유형 · 착안사항 대조 · 쟁점 · 목차
                  │
                  ▼
 ◆관문①  검수관 ──▶ 02_설계판정.md   GO / NO-GO   (NO-GO면 설계자 개정 1회)
                  │
                  ▼
 ★쟁점 승인  사용자 ── 쟁점 넣기·빼기·순서 바꾸기 → 00_요청.md에 추가 기록
                  │
                  ▼
   자료조사관 ×N ─▶ 03_근거장부.md   숫자마다 출처·조회일·〔원문〕〔계산〕〔잠정〕  (쟁점별 동시 투입)
                  │
                  ▼
   집필가 ──────▶ 04_검토보고서.md   Ⅰ → 【】 → < > → 1. → 가.  결론→근거→해명→반박→조치
                  │
                  ▼
 ◆검산 게이트  fiscal_check.py ─▶ 04b_검산결과.md   불통과면 집필가 수정(최대 2회), 그래도면 보류
                  │
                  ▼
 ◆관문②  검수관 ──▶ 05_검수판정.md   [필수]면 집필가 수정 1회
                  │
                  ▼
   변환가 ──────▶ 06_검토보고서.hwpx   예결위 번호 체계 그대로
                  │
                  ▼
 [팀장] 최종 보고 — 사람이 판정할 것: [확인 필요] · 〔판단 필요〕 · 검산 확인 필요 · 미반영 권고
```

## 2. 팀원

| 팀원 | 파일 | 하는 일 | 도구(권한) | 모델 | 산출 |
|---|---|---|---|---|---|
| 팀장 | `skills/budget-review/SKILL.md` | 순서대로 부르고 관문에서 멈춘다 | (메인 세션) | 세션 모델 | 00, 04b, 최종 보고 |
| 검토설계자 | `agents/budget-designer.md` | 사업 개요·재원 유형·착안사항 대조·쟁점·목차 | 읽기·쓰기·웹 | inherit | 01 |
| 검수관 | `agents/budget-reviewer.md` | 관문①·② 판정 | **읽기·웹만 — 쓰기 없음** | inherit | 02·05(응답 → 팀장이 저장) |
| 자료조사관 | `agents/budget-investigator.md` | 숫자와 근거 수집, 출처 병기 | 읽기·쓰기·웹·셸 | sonnet | 03 |
| 집필가 | `agents/budget-writer.md` | 검토보고서 문체로 집필 | 읽기·쓰기·셸(검산용) | inherit | 04 |
| 검산 게이트 | `skills/fiscal-rules/scripts/fiscal_check.py` | 단위·합계·관계식·증감·분모·음수 표기 검산 | 스크립트 | — | 04b |
| 변환가 | `agents/budget-exporter.md` | 한글 문서로 조판 | 읽기·쓰기·셸·kordoc | haiku | 06 |

**모델 배치의 이유** — 판단이 품질을 정하는 자리(설계·집필·검수)는 세션 모델을 그대로 쓰고(`inherit`),
찾아 모으는 조사는 `sonnet`, 절차가 정해진 변환은 가벼운 `haiku`가 맡는다. 검수관의 모델은 어떤 경우에도 낮추지 않는다.

## 3. 뜯어보기 순서

1. **`agents/budget-reviewer.md` 맨 위 머리말** — `tools:` 줄에 Write·Edit·Bash가 없다. 검수관은 고칠 수 없고 지적만 한다.
   부탁("고치지 마")이 아니라 **구조**로 막은 것이다. Ⅴ장에서 만든 검산관과 같은 원리다
2. **`agents/` 다섯 파일의 머리말** — `name`(이름) · `description`(언제 부르나) · `tools`(무엇을 할 수 있나) · `model`(누가 생각하나)
3. **`skills/budget-review/SKILL.md`** — 팀장의 공정. "승인 전에는 조사로 넘어가지 않는다", "검산 게이트는 생략하지 않는다" 같은 규칙이 문장으로 있다
4. **`skills/review-check/SKILL.md`** — 관문 판정서 양식. 모든 지적은 **위치 · 문제 · 권고** 세 칸이다
5. **검산기를 직접 돌려 본다**
   ```bash
   python3 <플러그인 폴더>/skills/fiscal-rules/scripts/fiscal_check.py --selftest
   python3 <플러그인 폴더>/skills/fiscal-rules/scripts/fiscal_check.py <플러그인 폴더>/skills/fiscal-rules/tests/sample_bad.md
   ```
   두 번째는 일부러 틀린 표라 **불통과(종료코드 1)** 가 나와야 정상이다
6. **`skills/review-criteria/references/` 한 파일** — 표준교재의 착안사항을 점검 질문으로 새로 쓴 것. 질문마다 교재 쪽이 달려 있다

플러그인 폴더 위치는 "budget-review 플러그인이 설치된 폴더 경로 알려줘"라고 물으면 된다.

## 4. 사람이 서는 자리 — 세 곳

| 자리 | 언제 | 사람이 하는 일 |
|---|---|---|
| ★쟁점 승인 | 설계 판정 뒤, 조사 전 | 쟁점을 넣고 빼고 순서를 바꾼다. 승인 전에는 팀이 조사로 넘어가지 않는다 |
| 검산 결과 판정 | 검산 게이트 뒤 | △(확인 필요) 항목이 실제 문제인지 원자료로 본다 |
| 최종 판정 | 산출 뒤 | `[확인 필요]`(사실 확인) · `〔판단 필요〕`(지적 여부·해명 수용·어조)를 하나씩 정한다 |

**검산 통과와 검수 통과는 초안이 맞다는 보증이 아니다.** 원자료에서 잘못 옮긴 값, 회계연도 착오, 조문 번호는 원문 대조로만 잡힌다.

## 5. 내 팀으로 고치기

| 바꾸고 싶은 것 | 고칠 곳 | 왜 거기인가 |
|---|---|---|
| 내가 자주 보는 검토 기준 | 작업 폴더의 `내_검토기준.md` | 설계자가 읽어 착안사항 대조표에 더한다. 플러그인 업데이트에 지워지지 않는다 |
| 매번 지킬 규칙(단위·연도·금지 표현) | 작업 폴더의 `CLAUDE.md` (`CLAUDE.template.md` 참고) | 모든 팀원이 일할 때마다 읽는다 |
| 팀원의 역할·공정 자체 | 이 저장소를 내 계정으로 복제(fork)해 `agents/`·`skills/`를 고친 뒤 그 주소로 설치 | 설치된 플러그인 폴더를 직접 고치면 업데이트 때 덮어써진다 |
