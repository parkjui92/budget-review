# examples — 완주 예시

## 지역소공인육성_2025결산 — 중소벤처기업부 「지역소공인육성 사업」 2025회계연도 결산 (2026-10-09)

공개 자료만으로 사업 한 건을 끝까지 돌린 산출물이다. 요청은 README의 예시 문형 그대로였다.
> 중소벤처기업부 지역소공인육성 사업(보조금)의 2025회계연도 결산 검토보고서 검토항목 초안을 써줘. 관점은 집행 부진과 이월·불용 반복이야

**가림 조건으로 돌렸다** — 끝난 뒤 실물과 견주려고, 국회의 2025회계연도 결산 검토보고서·국회예산정책처 결산 분석·2025회계연도 시정요구·2027년도 예산안 검토보고서는 팀원 누구도 열지 않았다. 대조는 `07_실물대조.md`.

### 읽는 순서
`_workspace/` 안에서

| 파일 | 무엇 | 관전 포인트 |
|---|---|---|
| `00_요청.md` | 요청 원장 | ⑤의 사용자 발언 두 줄('승인'·'진행')이 공정의 두 관문이다 |
| `01_검토설계.md` | 검토설계 | §1에서 요청의 '사업'이 기금 세부사업 「소공인특화지원」 안의 **내역사업**임을 찾았다. 끝의 「2차 반영」이 조사 뒤 재구성 |
| `02_설계판정.md` | 관문① | [필수] **세부사업 수치를 내역사업의 것으로 읽지 말 것**(귀속 규칙) → 개정 → 재판정에서 개정이 낳은 단위 섞임을 다시 잡음 |
| `03_근거장부.md` | 근거 장부(조사관 5명 합본) | 분할 A가 **설계 전제를 뒤집었다** — 기금 단계에는 이월·불용 반복이 없다(이월 0, 불용 1회). 반복은 지자체 단계의 복합지원센터 구축 보조금에 있었다 |
| `04_검토보고서.md` | 검토항목 초안 | `[확인 필요]` 13 · `〔판단 필요〕` 4 — 사람이 판정할 자리 |
| `04b_검산결과.md` | 검산 게이트 | 표 4개 통과(수정 전·후 두 번) |
| `05_검수판정.md` | 관문② | [필수] 부처 진술(2025. 6. 말 실집행)을 사실로 단정한 곳, 3곳분 합계를 전체처럼 쓴 곳 → 반영 확인 |
| `06_검토보고서.hwpx` | 한글 문서 | `06_변환보고.md` 끝의 팀장 확인 — 변환가 자기보고의 개수 오류를 다시 세어 바로잡음 |
| `07_실물대조.md` | 실물 대조 | 지적 대상·부처 해명·반박 방향·조치 요구가 실물과 일치. 모자란 것은 대부분 자료요구로 받아야 하는 부처 제출자료였다 |
| `_진행기록.md` | 단계별 시각 | |

관전 포인트는 완성본이 아니라 **관문이 무엇을 잡아냈는지**와 **조사가 설계를 뒤집었을 때 공정이 어떻게 멈췄는지**다.

### 이 예시를 돌리며 플러그인에 반영한 것
- `fiscal_check` 0.2.1 — 기금 표(`계획액·계획변경·계획현액`)를 읽지 못해 틀린 표를 통과시키던 결함
- `table-templates` 표 E′(기금 사업별 결산)
- `budget-sources` §3-1 — 키 없이 검토보고서 원문을 받는 경로(예결위 의안 목록 → 의안정보시스템)
- `budget-designer` — 전년 지적의 1순위 자료원은 직전 연도 소관 상임위 예비심사 검토보고서

### 저장소에 없는 것
- 팀이 내려받은 공개 원문(국회예산정책처 분석서 10종, 국회 검토보고서 4종 — 83MB)은 `.gitignore`로 뺐다. 받는 곳은 `_workspace/00_input/_목록.md`
- 실행 방식: 플러그인을 설치하지 않은 PC에서 팀원 정의(`agents/*.md`)를 읽힌 에이전트로 공정을 밟았다. 설치본과 프롬프트 경로만 다르다
