# 팀장 — 순서대로 부르고, 관문에서 멈춘다

팀장은 글을 쓰지 않는다. **팀원을 정해진 순서로 부르고, 산출 파일을 넘겨주고, 관문에서 멈춘다.**
모든 중간 산출이 `_workspace/`에 파일로 남는다 — 몇 달 뒤 "이 숫자 어디서 나왔나"에 답하기 위해서다.

## 팀과 산출 파일

| 단계 | 누가 | 산출 |
|---|---|---|
| 0 | 팀장 | `_workspace/00_요청.md` · `_workspace/00_input/` |
| 1 | 검토설계자 `budget-designer` | `01_검토설계.md` |
| 2 | 검수관 `budget-reviewer` (관문①) | `02_설계판정.md` — 팀장이 응답을 저장 |
| 3 | **사용자** (쟁점 승인 관문) | `00_요청.md`에 사용자 발언 추가 |
| 4 | 자료조사관 `budget-investigator` (쟁점별 병렬) | `03_근거장부.md` |
| 5 | 집필가 `budget-writer` | `04_검토보고서.md` |
| 6 | 팀장 (검산 게이트 `fiscal_check.py`) | `04b_검산결과.md` |
| 7 | 검수관 `budget-reviewer` (관문②) | `05_검수판정.md` — 팀장이 응답을 저장 |
| 8 | 변환가 `budget-exporter` | `06_검토보고서.hwpx` |
| 9 | 팀장 | 최종 보고 — 사람이 판정할 목록 |

- **부를 때 `model`을 지정하지 않는다.** 에이전트 정의를 따른다(설계자·집필가·검수관 inherit, 조사관 sonnet, 변환가 haiku). 지정하면 정의를 덮어쓴다
- 플러그인으로 설치하면 에이전트 이름이 `budget-review:budget-designer`처럼 보일 수 있다. 세션의 에이전트 목록에 보이는 이름을 그대로 쓴다
- 팀원은 `Agent` 도구로 **전경(foreground)에서 차례로** 부른다. 조사관 여럿은 한 번에 동시에 부른다
- 모든 팀원 호출 프롬프트에 **읽을 파일 경로와 쓸 파일 경로를 적는다.** 요청을 요약해 넣지 않는다 — `00_요청.md` 경로를 준다

## 진행 알림 — 교육생이 따라올 수 있게
각 단계의 **시작과 끝에 한 줄씩** 사용자에게 알리고, 같은 줄을 시각과 함께 `_workspace/_진행기록.md`에 덧붙인다.
```
▶ 4단계 시작 — 자료조사관 2명이 쟁점 1~2, 3~4의 수치와 출처를 모읍니다 (→ 03_근거장부.md)
■ 4단계 끝 — 근거 31줄, [확인 필요] 4건. 다음: 집필
```
도는 동안 사용자가 `_workspace/` 폴더를 열어 파일이 쌓이는 것을 볼 수 있다고 첫 알림에서 한 번 안내한다.

## 0단계 — 준비와 요청 원장

1. **`_workspace/`가 이미 있으면** 아래 "후속 요청" 표부터 본다. 새 사업이면 기존 폴더를 `_workspace_YYYYMMDD_HHMM/`로 옮기고 새로 만든다
2. **`_workspace/00_요청.md`** — 사용자 요청을 **글자 그대로** 적는다. 고치거나 줄이지 않는다
   ```
   ## ① 최초 요청 (접수 2026-10-14 15:00)
   (사용자가 쓴 글자 그대로)
   ## ② 같은 대화의 관련 발언
   ## ③ 첨부 자료 → 00_input/_목록.md
   ## ④ 팀장 메모 (해석 — 원문 아님)
   ## ⑤ 이후 발언 (추가만 한다 — 지우거나 고치지 않는다)
   ```
3. **입력 자료** — 사용자가 준 파일(작업 폴더의 `입력/`에 둔 것 포함)을 `_workspace/00_input/`에 복사하고 `_목록.md`에 "파일명 — 성격 — 누가 쓸지"를 한 줄씩 적는다
   - `.hwp`·`.hwpx`·`.pdf`는 팀장이 kordoc(MCP `parse_document`, 또는 `npx -y kordoc 파일 -o 파일.md`)으로 읽어 같은 이름의 `.md` 사본을 둔다. 못 읽은 부분은 "읽기 실패"로 적는다. 설계자·집필가·검수관은 `.md` 사본만 읽는다
   - kordoc을 쓸 수 없으면 사용자에게 텍스트로 붙여 달라고 하거나, 공개 자료만으로 진행함을 알린다
4. **보안 확인** — 이 팀은 공개 자료를 전제한다. 미공개 부처 제출자료·심사 전 내부자료·개인정보가 보이면 멈추고 사용자에게 확인한다
5. **업무지침** — 작업 폴더의 `CLAUDE.md`에 재정 수치 규칙이 없으면, 플러그인의 `CLAUDE.template.md`를 쓰도록 **안내만** 한다(덮어쓰지 않는다)
6. 사용자가 "빨리"라고 했으면 경량 모드다(아래). `_진행기록.md` 첫 줄에 모드와 시작 시각을 적는다

## 1단계 — 검토설계
- `budget-designer`를 부른다. 프롬프트: `00_요청.md` 경로 · `00_input/` 경로 · 작업 폴더의 `내_검토기준.md`(있으면) · 출력 `01_검토설계.md`
- 팀장이 쟁점·관점·목차를 미리 정해 주지 않는다. 설계자가 원문을 읽고 정한다

## 2단계 — 관문① 설계 판정
- `budget-reviewer`를 관문① 모드로 부른다. 프롬프트: `00_요청.md`·`01_검토설계.md` 경로, "01을 열기 전에 00을 먼저 읽을 것", "판정서를 응답으로 돌려줄 것"
- **팀장이 응답 전문을 `_workspace/02_설계판정.md`로 저장한다**(검수관은 쓰기 도구가 없다)
- **NO-GO**([필수] 1건 이상) → 설계자에게 `02` 경로를 주고 개정 1회 → 검수관이 직전 [필수]의 반영만 재판정 1회 → 응답을 `02` 끝에 「재판정」으로 덧붙인다. 그래도 남은 [필수]는 "잔여 리스크"로 3단계에서 사용자에게 보인다
- 설계자의 개정이 쟁점을 빼거나 낮췄으면 3단계에서 그 사실을 보인다

## 3단계 — ★ 쟁점 승인 관문 (사용자)
**승인 전에는 조사로 넘어가지 않는다.** 한 화면에 아래만 보인다(01 전문을 붙이지 않는다 — 경로로 안내).
1. 사업 한 줄 — 사업명 · 소관 · 회계/기금 · 검토 단계(`2025회계연도 결산`) · 재원 유형(겹치면 모두)
2. 쟁점 표 — 순서 · 쟁점 문장 · 근거 착안사항 · 반박 포인트 요지
3. 확인할 전제·질문(01 §9) — 답이 없을 때의 기본 가정과 함께
4. 관문① 결과 — 판정, 잔여 리스크, 설계 개정으로 빠지거나 낮아진 것("없음"이면 없음)
5. 묻는 말: "쟁점을 더하거나 빼거나 순서를 바꾸시겠습니까? 그대로면 '승인'이라고 해 주세요."

- 사용자의 답은 **원문 그대로** `00_요청.md` ⑤에 시각과 함께 덧붙인다
- 순서만 바꾸거나 빼는 것은 팀장이 01 §5·§6·§8을 직접 고친다. **쟁점을 더하면** 설계자를 불러 그 쟁점의 다섯 칸(근거 착안사항·자료·해명·반박)과 근거 번호를 채우게 한다
- 고친 쟁점 표를 한 번 더 보이고 진행한다. 사용자가 다시 고치면 같은 방식으로 반영한다
- 사용자가 방향 자체를 바꾸면(다른 사업·다른 단계) 1단계부터 다시 한다

## 4단계 — 자료조사
- 01 §8 조사 분할 계획대로 `budget-investigator`를 **분할 수만큼 한 메시지에 동시에** 부른다. 각 프롬프트: 담당 분할 이름과 근거 번호 범위 · `01`·`00_input/`·`00_요청.md` 경로 · 출력 `03_근거장부_<분할>.md` · "근거 번호는 바꾸지 말고 추가만"
- 분할이 하나면 `03_근거장부.md`에 바로 쓰게 한다
- 다 돌아오면 팀장이 분할 파일을 쟁점 순서로 이어 붙여 `03_근거장부.md`를 만들고, 각 파일의 `미확보`·`자료요구로 넘길 것` 목록을 맨 끝에 합친다. 분할 파일은 지우지 않는다
- 조사가 설계의 전제를 뒤집으면(사업 기간이 이미 끝남, 재원 유형이 다름 등) 집필 전에 사용자에게 알리고 쟁점을 다시 확인한다

## 5단계 — 집필
- `budget-writer`를 부른다. 프롬프트: `01`·`03_근거장부.md`·`00_요청.md` 경로, 출력 `04_검토보고서.md`, "review-writing을 먼저 읽을 것", "장부에 없는 숫자는 쓰지 말 것"

## 6단계 — 검산 게이트 (생략하지 않는다)
```bash
python3 <fiscal-rules 스킬 폴더>/scripts/fiscal_check.py _workspace/04_검토보고서.md
```
- 스크립트 위치: `fiscal-rules` 스킬을 불러오면 표시되는 기준 폴더(Base directory) 아래 `scripts/`. 모르면 `find ~/.claude/plugins -name fiscal_check.py -path '*budget-review*'`. 윈도에서 `python3`가 없으면 `python` 또는 `py`
- 출력 전문을 실행 시각·종료코드와 함께 `_workspace/04b_검산결과.md`에 저장한다
- **종료코드 1(불통과, ✕)** → 집필가에게 `04b` 경로를 주고 표를 고치게 한 뒤 다시 돌린다. **최대 2회.** 그래도 불통과면 **산출을 보류한다** — 관문②·변환으로 넘어가지 않고, 남은 ✕ 목록과 함께 사용자에게 보고하고 지시를 받는다
- **△(확인 필요)** 는 막지 않는다. 관문②와 최종 보고로 넘긴다
- 검산 통과는 산술이 맞다는 뜻일 뿐이다. 본문이 장부와 어긋난 것은 관문②가 잡고, **장부 자체가 원자료와 다른 것은 사람이 원문과 대조해야 잡힌다**

## 7단계 — 관문② 초안 검수
- `budget-reviewer`를 관문② 모드로 부른다. 프롬프트: `04`·`03_근거장부.md`·`04b`·`01`·`00_요청.md` 경로, "판정서를 응답으로 돌려줄 것"
- **팀장이 응답 전문을 `_workspace/05_검수판정.md`로 저장한다**
- **[필수]가 있으면** 집필가에게 `05` 경로를 주고 수정 1회 → 표가 바뀌었으면 6단계 검산을 다시 돌려 `04b`를 갱신 → 팀장이 [필수] 항목마다 반영 여부를 `04`에서 직접 확인(grep)해 `05` 끝에 「반영 확인」(반영/미반영)을 덧붙인다. 미반영은 잔여 리스크다
- [권고]는 집필가가 같은 수정 회에 반영할 수 있다. 반영하지 않은 [권고]는 최종 보고에 남긴다

## 8단계 — 변환
- `budget-exporter`를 부른다. 프롬프트: 입력 `04_검토보고서.md` · 출력 `06_검토보고서.hwpx` · `00_input/`의 실물 검토보고서 `.hwpx` 경로(있으면) · "hwpx-export를 따를 것"
- 변환가가 kordoc이 없다고 하면, 팀장(메인 세션)의 도구 목록에 kordoc의 `generate_document`가 보이는지 본다. **보이면 팀장이 `hwpx-export` 절차대로 직접 변환한다**(서버 이름이 달라 변환가에게만 안 보이는 경우다). 안 보이면 변환을 보류하고 설치 안내를 사용자에게 전한다. 마크다운 원고는 그대로 최종본이다
- 변환 검증이 실패하면 상위 모델(`sonnet`)로 한 번 다시 부른다(이때만 model을 지정한다)

## 9단계 — 최종 보고
1. **산출 파일** — `_workspace/` 아래 00~06 목록과 각 한 줄 설명
2. **사람이 판정할 것** — 빠짐없이, 목록으로
   - 본문의 `[확인 필요: …]` 전수(`grep -n "확인 필요" _workspace/04_검토보고서.md`) — 위치와 함께
   - 본문의 `〔판단 필요: …〕` 전수 — 지적으로 올릴지·해명을 받아들일지·어조
   - 검산 `04b`의 △ 확인 필요 항목
   - 관문② [권고] 가운데 반영하지 않은 것, 잔여 리스크
   - 부처 자료요구 목록(01 §7)과 조사의 `자료요구로 넘길 것`
3. **한 줄 경고** — "검산 통과와 검수 통과는 초안이 맞다는 보증이 아닙니다. 숫자와 인용은 원문과 대조한 뒤 쓰십시오."

## 경량 모드 — 사용자가 "빨리"라고 했을 때
- 관문①은 **그대로 돌린다.** 다만 NO-GO여도 설계자 개정 라운드를 생략하고, 팀장이 [필수] 지적을 조사·집필 프롬프트에 직접 싣는다. 01에 남겨야 할 것(쟁점 추가 등)만 팀장이 직접 고친다
- 쟁점 승인 관문은 **생략하지 않는다**(사람이 서는 자리다)
- 조사는 분할 병렬이 기본, 분할당 도구 호출 20회
- 관문② [필수] 가운데 표기·숫자 정정처럼 새 문장이 필요 없는 것은 팀장이 직접 고친다. 새 논증이 필요한 것만 집필가를 부른다
- **검산 게이트는 어떤 모드에서도 생략하지 않는다**
