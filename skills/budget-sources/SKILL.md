# 예결산 자료원 — 어디서, 어떻게, 무엇은 못 구하나

2026-09-13 기준으로 **실제 접속·호출로 확인한 것**을 적었다. 확인하지 못한 것은 〔미확인〕이다.
기관 개편·시스템 개편으로 경로가 바뀔 수 있다 — 링크가 죽어 있으면 그 사실을 장부에 적는다.

> ※ **정부조직이 개편됐다.** 예산·성과관리 소관은 **기획예산처**(`mpb.go.kr`), 결산·국고·세제는 **재정경제부**(`mofe.go.kr`),
> 통계는 **국가데이터처**다. 옛 `moef.go.kr` 링크가 실린 자료는 갱신 전 것이다.
> 생성형 AI는 개편 전 이름을 확신에 찬 어조로 내놓는다 — **기관명은 인용 전에 확인한다.**
> 다만 **과거 시점의 집행 주체는 그 시점의 이름 그대로** 둔다(`fiscal-rules` §9).

## 1. 인증키 — `.env`에 두고, 채팅창에 붙이지 않는다

작업 폴더에 `.env` 파일을 만들고 키를 적는다. 키 이름은 아래로 통일한다(없는 키는 빼도 된다).
```
OPENFISCAL_KEY=...      # 열린재정 OpenAPI
ASSEMBLY_KEY=...        # 열린국회정보 (없으면 sample 키로 5건만)
LAW_OC=...              # 국가법령정보 공동활용 인증값
DATA_GO_KR_KEY=...      # 공공데이터포털(나라장터 등)
KOSIS_KEY=...           # KOSIS
```
- **키를 채팅창에 붙여 넣지 않는다.** 대화 기록에 남는다. 사용자가 붙여 넣었으면 `.env`로 옮기고 키 재발급을 권한다
- `.env`는 git에 올리지 않는다(플러그인 `.gitignore`가 막는다. 작업 폴더에도 같은 줄을 둔다)
- 조회는 셸 변수로만 한다 — **명령어에 키 값을 직접 쓰지 않는다.** `-v` 같은 상세 출력을 켜지 않는다(URL이 찍힌다)
```bash
set -a; . ./.env; set +a
curl -s "https://open.assembly.go.kr/portal/openapi/BUDGETJUDGE?KEY=${ASSEMBLY_KEY:-sample}&Type=json&pIndex=1&pSize=5"
```
- 장부에 URL을 적을 때는 키 자리를 `KEY=〔키〕`로 가린다
- 윈도에서 메모장으로 `.env`를 만들면 줄 끝 문자 때문에 키가 깨질 수 있다. 조회가 키 오류로 실패하면 `sed -i 's/\r$//' .env` 후 다시 한다

**OPEN API** — `https://openapi.openfiscaldata.go.kr/{서비스명}?Key=${OPENFISCAL_KEY}&Type=json`
(인증키 파라미터명은 대문자 `Key`. 오류코드 `ERROR-290` 키 무효 / `ERROR-310` 서비스 없음).
예결위 관점에서 쓸모가 큰 계열은 **이월 추이**와 **불용 추이**(회계·기금별 / 분야별 / 성질별)다.
〔미확인〕 결산·집행·국가채무 계열의 영문 서비스명 전체 목록, 호출 제한 수치.

> **집행실적은 잠정치다.** 열린재정이 "결산 검증 절차를 거쳐 변경될 수 있다"고 밝힌다.
> 장부에 **조회일과 〔잠정〕** 을 붙인다. 심사 중 인용한 집행률이 확정 결산에서 바뀌면 그 지적은 사후에 틀린 것이 된다.

## 3. 열린국회정보 — 예결위 전용 API

`https://open.assembly.go.kr/portal/openapi/{서비스ID}` · 인증키는 국회 SSO 로그인 후 발급
(`KEY`·`Type`·`pIndex`·`pSize`. **`KEY=sample`은 키 없이 5건만** 돌려준다 — 실습용)

| 서비스 | 서비스ID | 무엇이 나오나 |
|---|---|---|
| **예결산 심사정보** | `BUDGETJUDGE` | 예결위 회부일·상정일·의결일·처리결과, 한글파일 주소 |
| **예결산 예비심사 정보** | `BUDGETADJUDGE` | 상임위 예비심사 결과 + **예비심사 검토보고서 원문 주소** (`BILL_ID` 필요) |
| 예결산 종합심사 회의정보 | `BUDGETJUDGECONF` | 종합심사 회의명·회의일·결과 (`BILL_ID` 필요) |
| 예결위 회의록 | `VCONFBUDGETCONFLIST` | 회기·차수·회의일·다운로드 주소 |
| 본회의 처리안건 — 결산 | `nkalemivaqmoibxro` | |
| 본회의 처리안건 — 예산안 | `nzgjnvnraowulzqwl` | 추경·기금운용계획변경안 포함 |
| 국정감사 결과보고서 | `AUDITREPORTRESULT` | 위원회별 보고서 PDF |

- `BUDGETADJUDGE`로 **예비심사 의견과 종합심사 결과의 차이**를 대조할 수 있다. `BILL_ID`는 `BUDGETJUDGE`로 먼저 얻는다(두 단계 호출)
- 널리 퍼진 "본회의 처리의안 — 결산=`nwbpacrgavhjryiph`" 매핑은 **틀렸다**(그 ID는 법률안이다)
- 의안정보시스템 **예결산 심사연혁** `https://likms.assembly.go.kr/bill/bi/nafs/stats/inscHstPage.do` — 연도별 정부안 → 증액 → 감액 → 국회확정

## 4. 국가법령정보 — 조문은 원문으로 확인한다

`https://open.law.go.kr/LSO/main.do` · 무료, 공동활용 신청(인증값 = 이메일 ID → `.env`의 `LAW_OC`)
```
목록  https://www.law.go.kr/DRF/lawSearch.do?OC=${LAW_OC}&target=law&type=JSON&query=국가재정법
본문  https://www.law.go.kr/DRF/lawService.do?OC=${LAW_OC}&target=law&MST={일련번호}&type=JSON
```
`target`: `law`(법령) · `admrul`(행정규칙) · `ordin`(자치법규) · `prec`(판례) · `expc`(해석례).
korean-law MCP를 연결했으면 그것으로 조회해도 된다.

> 성과관리 근거로 널리 인용되는 `국가재정법 제8조`는 **2021. 12. 21. 삭제**됐고 현행은 **제4장의2(제85조의2~제85조의12)** 다.
> 기관 안내 페이지에도 옛 조문이 남아 있다 — 웹이 오염돼 있고 AI는 그것을 학습했다. **기억으로 조문을 쓰지 않는다.**
> `review-criteria` 파일의 제도 요점은 2024년 8월 기준이다. 인용 전에 현행을 확인한다.

## 5. 감사원 — 공식 OPEN API는 없다

| 화면 | 경로 | 비고 |
|---|---|---|
| 분야·종류별 감사결과 | `https://www.bai.go.kr/bai/result/branch/list/` | 감사보고서 전문 PDF |
| **기관별 감사결과** | `https://www.bai.go.kr/bai/result/organ/list/` | **처분요구 단위** — 기관명·처분 종류·요지 |

- 이용조건 **공공누리 제4유형**(출처표시·상업적 이용금지·**변경금지**). 내부 검토자료와 발간물은 조건이 다르다
- 공공감사포털 `https://www.pap.go.kr/` — 공공감사법 대상기관의 **자체감사** 결과
- 감사원 처분요구와 국회 시정요구는 **다른 제도**다(`audit-followup`)

## 6. KDI PIMAC — 예비타당성조사

`https://pimac.kdi.re.kr/` · 인증 불필요
- 예비타당성조사보고서 `/study/study_list.jsp?classcd=F1` · 타당성재조사 `F2` · 심층평가 `F5` · 조세특례 평가 `F8`
- **재정사업 조사현황** `/study/fina_list_status.jsp` — 조사의뢰 → 착수 → 점검회의 → 평가위원회 → 완료
- 신규 사업명을 조회해 **조사 완료 전인데 예산이 반영됐는지** 본다(SOC·R&D 쟁점)

## 7. 나라장터 · 통계

- **나라장터** — 공공데이터포털 활용신청 → `https://apis.data.go.kr/1230000/…`(자동승인, 개발계정 일 1,000건). 낙찰·계약·계약변경이력.
  웹은 조달데이터허브 `https://data.g2b.go.kr/`(계약방법별 수의계약 비중). **집행률 100%인데 계약이 12월에 몰려 있으면** 형식적 집행이다
- **KOSIS** `https://kosis.kr/openapi/` — 통계표를 연 뒤 툴바 `OPENAPI` 버튼이 호출 주소를 만들어 준다
- **NABOSTATS** `https://www.nabostats.go.kr/` — 국회예산정책처. **「결산 시정요구 및 조치결과」**(엑셀) — `audit-followup`의 출발점

## 8. 공개 창구로는 못 구한다 — 자료요구 대상

| 무엇 | 왜 |
|---|---|
| **dBrain⁺** | 공무원 업무망 전용. 공개 창구는 열린재정뿐이고 세부사업 단위 집계가 최말단이다 |
| 성과계획서·보고서의 **기계가독 형태** | 정부가 한글·PDF로만 제공한다 |
| 재난안전·일자리 사업평가의 **사업별 결과** | 보도자료만 공개, 사업별 결과는 예산실에만 간다 |
| 개별 계약·지급 **건별 내역**, 보조사업자 단계 **실집행** | 열린재정은 총액 수준이다 |

이 넷은 "확인 불가"가 아니라 **"자료요구로 받아야 하는 것"** 이다. 01 §7 부처 자료요구 목록과 장부의 `자료요구로 넘길 것`에 올린다.
문서에 "dBrain에서 조회"라고 쓰지 않는다.

## 9. 출처 우선순위
1. **확정 결산치**(국가결산보고서·감사원 결산검사 후) 2. **열린재정 공표치**(재현 가능, 집행실적은 잠정) 3. **부처 제출자료**(상세하지만 기준이 다를 수 있다).
수치가 어긋나면 둘 다 적고 차이의 원인을 쓴다. 한쪽을 조용히 고르지 않는다.
