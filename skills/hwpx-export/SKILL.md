# 한글 문서로 옮기기 — 번호를 지키고, 빠진 것이 없음을 숫자로 보인다

검토보고서는 한글 문서로 돈다. 변환에서 **번호 체계가 바뀌거나 표 한 행이 빠지면** 내용이 맞아도 쓸 수 없다.
그래서 변환가는 문장을 고치지 않고, 대신 **변환 전후를 숫자로 맞춰 보인다.**

> **의존성** — kordoc(제3자 오픈소스, `github.com/chrisryugj/kordoc`). 설치: `claude mcp add kordoc -- npx -y kordoc@latest mcp`
> (Node.js 20 이상). 없으면 변환을 보류하고 마크다운 원고를 최종본으로 둔다.

## 1. 시작 조건
- `05_검수판정.md`가 "통과"이거나, [필수] 뒤 「반영 확인」이 붙어 있어야 한다. 아니면 시작하지 않고 팀장에게 알린다
- `00_input/`에 실물 검토보고서 `.hwpx`가 있는지 본다(있으면 3-B). `.hwp`만 있으면 한글에서 `.hwpx`로 저장해 달라고 안내한다

## 2. 전처리 → `_workspace/06a_변환용.md`
원고를 복사해 아래만 손본다. **문장·숫자·`[확인 필요]`·`〔판단 필요〕` 표시는 그대로 둔다** — 사람이 판정할 자리다.
- 제목 단계가 `review-writing` §12 표기 약속(`#`~`#####`)과 맞는지 확인한다. 어긋나면 고치지 말고 팀장에게 알린다
- 문단 맨 앞의 `-`·`*` 목록 기호는 원고에 없어야 한다. 있으면 위치를 보고한다(임의로 바꾸지 않는다)
- 날짜만 있는 한 줄(`2026. 10. 14.`)은 번호 목록으로 오인될 수 있다 — 문장 안에 있는지 확인한다
- 원고 끝의 작업 메모(있으면)만 뺀다

## 3. 변환

### 3-A. 기본 — 범용 모드
```
mcp__kordoc__generate_document(
  markdown = (06a_변환용.md 전문),
  output_path = (작업 폴더 절대경로)/_workspace/06_검토보고서.hwpx,
  font = "myeongjo"
)            ← preset 은 지정하지 않는다
```
**`preset`을 쓰지 않는 이유(실측, kordoc 4.x, 2026-10-07)** — `개조식`·`보고서` 같은 공문서 프리셋은
`【일반회계】`를 `□ 【일반회계】`로, `< 세  출 >`과 `가. 개  요`를 `○`로 바꾸고 `Ⅱ.`를 지운다.
범용 모드는 `Ⅱ.` `【 】` `< >` `1.` `가.` `(1)` `①` `[확인 필요]` `〔판단 필요〕` `주)` `자료:`를 **글자 그대로** 둔다.

### 3-B. 실물 검토보고서가 있을 때 — 그 표 서식을 따른다
1. `mcp__kordoc__extract_profile(hwpx_path=실물, output_path=_workspace/06b_서식프로필.json)`
2. 3-A 호출에 `profile_path`를 더한다 — 실물의 표 테두리·음영·열 너비·셀 글꼴이 재현된다
   (행·열 수와 첫 칸 글자가 같은 표에만 적용된다. 적용 안 된 표는 보고에 적는다)
3. 실물의 본문 글꼴·크기는 `parse_document`로 확인할 수 없다. 렌더 결과를 실물 렌더와 나란히 보고,
   다르면 `body_pt`·`fonts`·`line_spacing`으로 맞춘다. 끝내 다른 부분(머리말·쪽번호 모양·표지)은 보고에 적어 **한글에서 손으로 맞추게** 안내한다

### 3-C. 소형 시험 먼저
본 변환 전에 **첫 검토항목 하나**만 변환해 재파싱하고, 번호 부호가 살아 있는지 확인한 뒤 전체를 변환한다.

## 4. 검증 — 숫자로 1:1
`mcp__kordoc__parse_document`로 `06`을 다시 읽어 원고(`06a`)와 맞춘다.

| 항목 | 맞추는 법 |
|---|---|
| 표 개수 | 원고 표 수 = 문서 표 수 |
| 표 행 수 | 표마다 원고 행 수 = 문서 행 수. 의심되면 `parse_table`로 그 표만 |
| 번호 부호 | `Ⅰ.`·`Ⅱ.` · `【` · `< ` · `가.` · `첫째` 개수가 같다 |
| 표시 | `[확인 필요` 개수 = · `〔판단 필요` 개수 = |
| 본문 | 공백을 접어 비교한다 — 재파싱은 `개  요`의 겹칸을 한 칸으로 보여 준다(파일 안에는 겹칸이 남아 있다) |

- **개수가 어긋난 채로 "이상 없음"이라고 쓰지 않는다.** 어긋나면 고쳐 다시 만들고(최대 2회), 그래도 어긋나면 어긋난 그대로 보고한다
- **구조 검증** — `npx -y kordoc@latest validate _workspace/06_검토보고서.hwpx` (한글이 거부하는 구조 결함을 미리 잡는다)
- **렌더로 눈으로 본다** — `mcp__kordoc__render_document`. 숫자 대조는 겹침·잘림을 세지 못한다.
  MCP 렌더가 실패하는 환경이 있다(실측) — 그때는 `npx -y kordoc@latest render _workspace/06_검토보고서.hwpx -o _workspace/06c_미리보기.svg`로
  SVG를 만들어 연다. 둘 다 안 되면 "렌더 확인 못 함 — 한글에서 열어 확인 필요"로 보고한다

## 5. 보고 (변환가 응답)
```
06_검토보고서.hwpx 생성 — 범용 모드 · 표 서식: 기본 / 실물 공여(파일명, 적용 표 n/n)
검증: 표 n/n · 행 일치 n/n · 번호 부호 원고 n = 문서 n · [확인 필요] n = n · 〔판단 필요〕 n = n
렌더: 확인함 / 확인 못 함(사유)
형식 조정: (없음 / 무엇을 왜)
남은 손작업: (한글에서 맞출 것 — 머리말·쪽번호·표지 등)
```

## 6. 막힐 때
| 상황 | 대응 |
|---|---|
| kordoc 도구가 안 보임 | 변환 보류. 설치 명령을 팀장에게 돌려준다. 원고는 `04_검토보고서.md`가 최종본 |
| MCP 호출이 막힘 | **생성은 MCP로만 한다.** CLI `kordoc generate`에는 범용 모드가 없고, 기본값인 기안문 프리셋이 `나. 검토의견`을 `가.`로 다시 매긴다(실측). CLI는 읽기(`kordoc 파일`)·검증(`validate`)·렌더(`render`)·프로필(`profile`)에만 쓴다. 생성은 보류하고 보고 |
| 검증이 두 번 어긋남 | 상위 모델로 다시 불러 달라고 팀장에게 요청(haiku → sonnet) |
| 한글에 붙여 넣으니 표가 깨짐 | hwpx 자체는 정상일 수 있다(`parse_table`로 확인). 다른 문서에 넣을 때는 hwpx를 열어 표째 복사한다 |

## 하지 않는 것
- 문장·숫자를 고치거나 줄이기, 표시를 지우기
- 통과 전 원고 변환
- 실물 검토보고서 원본을 덮어쓰기 — 늘 새 파일로 만든다
