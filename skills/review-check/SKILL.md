# 두 관문의 판정 기준

실패는 두 곳에서 온다. **방향 실패** — 쟁점이 빗나간 채 조사·집필이 끝난다. **근거 실패** — 그럴듯한 문장 속에
장부에 없는 숫자, 지어낸 부처 해명, 반박 없는 지적이 섞인다. 성격이 달라서 관문이 둘이다.

| | 관문① 설계 판정 | 관문② 초안 검수 |
|---|---|---|
| 시점 | 설계 직후, 조사 전 | 집필·검산 후, 변환 전 |
| 대상 | `01_검토설계.md` | `04_검토보고서.md` |
| 대조 기준 | `00_요청.md` · `review-criteria` 해당 파일 · `내_검토기준.md` | `03_근거장부.md` · `04b_검산결과.md` · `01` · `00_요청.md` |
| 판정 | GO / NO-GO | 통과 / 수정 필요 |
| 저장 | 팀장이 `02_설계판정.md` | 팀장이 `05_검수판정.md` |

## [필수]와 [권고]

- **[필수]** — 그대로 두면 **틀린 보고서가 나가는 것.** 근거 없는 숫자, 반박 없는 지적, 빠진 쟁점, 요청과 다른 단계·사업, 지어낸 해명·출처, 검산 ✕ 잔존
- **[권고]** — 고치면 **나아지는 것.** 어조 한 단계 조정, 표현, 표 배치, 더 강한 근거로 바꿀 여지
- 판정 규칙: 관문①은 **[필수] 1건 이상이면 NO-GO**. 관문②는 [필수] 1건 이상이면 "수정 필요"
- 애매하면 "이게 위원 질의나 부처 반박에서 무너지는가"를 묻는다. 무너지면 [필수]

## 관문① 점검표 — 설계 판정

**먼저 `00_요청.md`만 읽고** 사업·검토 단계·관점을 따로 적는다. 그 뒤에 `01`을 연다.

| # | 볼 것 | [필수]가 되는 경우 |
|---|---|---|
| 1 | **요청 반영** — 사업·단계·관점·산출 범위가 01에 그대로 있는가 | 요청한 관점(예: 이월·불용)이 쟁점에서 빠지거나 뒤로 밀림 / 다른 사업·단계로 설계 |
| 2 | **사업 개요** — 소관·회계/기금·사업코드·기간·총사업비 | 모르는 값을 `[조사 필요]` 없이 채움 |
| 3 | **검토 단계·연도** — 예산안/결산, 회계연도 표기 | 단계 오판 / "작년·올해" 표기 |
| 4 | **재원 유형** — 세 축(회계·지출 성격·집행 주체) 판정과 근거 | 겹치는 유형을 빠뜨려 해당 파일을 안 읽음(예: 기금의 보조사업인데 6만 읽음) |
| 5 | **착안사항 대조표** — 읽은 파일의 단계별 착안사항 행이 빠짐없이 있는가 | 행 수가 파일과 다름(일괄 비해당 묶음은 행 수로 센다) / 이유 없는 비해당 |
| 6 | **쟁점** — 다섯 칸(쟁점 문장·근거 착안사항·근거 자료·부처 예상 해명·반박 포인트) | **반박 포인트 없음** / 근거 자료가 공개 자료로도 자료요구로도 구할 수 없음 / 쟁점 문장에 확인 안 된 숫자 |
| 7 | **목차** — `review-writing` 골격·번호 체계, 제목 `사업명: 지적 요지` | 쟁점과 목차가 1:1이 아님 |
| 8 | **자료요구 목록** — 공개 자료로 못 구하는 것만, 쟁점과 연결 | 열린재정에 있는 것을 자료요구로 돌림 / 쟁점에 필요한데 목록에 없음 |
| 9 | **조사 분할** — 근거 번호(`쟁점-항목`) 범위가 겹치지 않고 빠짐없음 | 번호 충돌 |
| 10 | **확인할 전제** — 질문마다 기본 가정이 있는가 | 쟁점을 가르는 전제를 묻지 않고 단정 |

**재판정(개정 뒤)** — 직전 [필수]마다 반영됐는지부터 본다. 두 번 지적했는데 남은 것은 "잔여 리스크"로 옮긴다.
**권고가 요청을 깎을 때** — 쟁점을 빼라고 권하면, 그러면 보고서에서 무엇이 빠지는지 함께 적는다. 뺄지는 사용자가 쟁점 승인 관문에서 정한다.

## 관문② 점검표 — 초안 검수 (여섯 축)

### 축 1 — 쟁점
- 승인된 쟁점(01 §5와 `00_요청.md` ⑤의 사용자 수정)이 **모두** 검토항목이 됐는가, 순서가 승인대로인가
- 승인받지 않은 쟁점이 검토항목으로 끼어들었는가
- 요청의 관점이 본문 분량에서도 앞에 서 있는가

### 축 2 — 수치 대조
- 본문·표의 숫자를 **장부와 하나씩** 맞춘다. 억원↔백만원 환산, `△` 부호, 회계연도까지
- 장부에 없는 숫자 = [필수]. 장부의 〔잠정〕 값을 본문이 확정치처럼 썼으면 [필수]
- 같은 숫자가 표와 본문에서 다르게 적혔는가(1,350억원 ↔ 135,070백만원 같은 반올림 차이 포함)
- 증감률·집행률에 분모가 적혀 있는가

### 축 3 — 지적의 짜임
- 결론 → 근거 → 부처 해명 → 반박 → 조치 요구가 갖춰졌는가
- **반박이 없는 지적 = [필수].** 해명 자리가 `〔판단 필요〕`로 비어 있으면 반박도 그만큼만 있어야 한다
- 어조가 근거의 무게를 넘는가 — 정황뿐인데 `부적정함`, 조문 원문 확인 없이 `법령을 위반한 것임`이면 [필수]
- **예산안 검토면** — `부적정`·`주의할 필요`·`위반`은 실물에서 거의 쓰지 않는다(2026년도 예산안 검토보고 495항목 중 제목 1건). 이미 일어난 집행·위법이 근거가 아니면 [권고]로 한 칸 내리게 한다(`review-writing` §13 ③). 표가 결산 열 구성(예산현액·불용액)으로 `가. 개요`를 채웠으면 [권고]로 표 G′를 권한다

### 축 4 — [확인 필요] · 〔판단 필요〕
- 장부의 `[확인 필요]`·미확보 항목이 본문에서 단정으로 바뀌지 않았는가 = 바뀌었으면 [필수]
- 지어낸 부처 해명·출처·조문이 있는가 = [필수]
- 표시가 지나쳐 문서가 읽히지 않는 정도인가 — 그러면 [권고]로 자료요구 목록에 넘길 것을 제안

### 축 5 — 검산
- `04b_검산결과.md`를 직접 읽는다(집필가의 "통과" 보고를 믿지 않는다). ✕가 남아 있으면 [필수]
- △(확인 필요) 항목을 본문이 어떻게 다뤘는가 — 무시했으면 [권고]로 처리 방법을 적는다
- 검산기가 못 보는 것: 원자료에서 잘못 옮긴 값 · 회계연도 착오 · 조문 번호 · 인용 문안 — 축 2에서 본다

### 축 6 — 문체·형식 (`review-writing` §10 점검 목록)
- 제목 `사업명: 지적 요지` · 번호 체계 Ⅰ → 【】 → < > → 1. → 가. · `첫째/둘째`
- 개조식 종결, `판단됨`·`사료됨` 없음, 해라체는 법령 박스 안에서만
- `△`·기관명·소수점 자리 원문 그대로, 법령명 홑낫표 `｢ ｣`, 표 단위 줄·`주)`·`자료:`
- `review-writing` §12 마크다운 표기 약속(변환가 계약) — 문단 앞 `-` 기호 등

### 그리고 — 점검표 밖을 한 번 훑는다
집필가는 받은 목록만 자기 점검한다. 결함은 목록 밖에서 나온다. **표와 본문의 숫자 일치, 각주·자료 표시의 짝,
같은 대상의 이름이 한 문서 안에서 흔들리는지**를 따로 본다.
